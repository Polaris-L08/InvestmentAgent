# Graph Workflow
AI Workflow 采用 Graph（图）结构，就是用“节点”代表处理步骤，用“边”代表数据与控制流的流向，从而构建出可循环、有条件分支、可并行的非顺序执行流程

## 1. Graph Workflow的核心构成
 - **节点（Node）**:工作流中的一个原子操作单元。每个节点接收输入，执行特定任务，并输出结果。常见的节点类型包括：
   - **LLM节点**：调用大模型进行推理、生成、结构化输出。
   - **工具节点**：执行具体函数，如检索向量数据库、调用API、计算、写文件等。
   - **条件节点**：不调用模型，只根据输入数据进行逻辑判断（如if/else），决定下一步走向。
   - **人机协同节点**：暂停流程，等待人工输入、审批或提供额外信息。
   - **子图节点**：将一个完整的Graph工作流内嵌为另一个Graph的节点，实现复用。
 - **边（Edge）**:连接节点的通道，定义了流程的可能性。主要分为两种：
   - **普通/直通边**：当源节点执行成功，无条件地将输出传递给目标节点。数据流与控制流合一。
   - **条件边**：源节点执行后，一个路由函数会根据输出结果，动态决定激活哪一条出边。这是Graph实现分支和决策能力的关键。
 - **状态（State)**：这是Graph设计模式的精髓。整个工作流维护一个**共享的、不可变（或可追加）的状态字典**。每个节点在执行时，可以读取这个字典中的任何信息，并写入自己的新结果。这使得不同节点之间能够灵活地交换和共享数据，而不必像Chain那样通过显式的参数传递。
